# Iteration 15 — first source-derived original OAM producer, `$D993–$DA45`

**Pinned original source:** [`bank_FF.asm`](https://github.com/cyneprepou4uk/NES-Games-Disassembly/blob/df2c8e55e7f13e5792482527db9e7c9e4a84c6e1/Kunio-kun%20no%20Nekketsu%20Soccer%20League/bank_FF.asm), blob SHA `d9b5307a83f022c17deb0cec82b2bea2249c5484`, source lines 4847–4945 and 4947–5025. The owner-provided NES 2.0 ROM normalizes to the pinned upstream assembled SHA-1 `edf933eee8d6b99b7743367eda089b9850ce51ec`; original 128 KiB PRG is read only from that verified user input.

This is the **actual original weather-effect sprite producer** (12 OAM entries), **not a player-character metasprite producer**. Source routine `sub_D993` selects RAM `$0466` effect states `$81` (initialize) and `$01` (update); other states immediately return. Native JavaScript `src/classic/OriginalWeatherSprites.js` reproduces the original RAM writes and 8-bit 6502 arithmetic. No original graphics, tables, ROM, or sound samples are embedded in public source; the five source tables are read from the user-selected private PRG at their original fixed-bank addresses.

| Original | Operation | Native JS |
|---|---|---|
| `$D993–$D99E` | Read weather effect `$0466`; dispatch `$81`, `$01`, otherwise RTS | `stepOriginalWeatherSprites` dispatch |
| `$D99F–$D9D7` | Loop 12 sprites; table Y `$DA5E`, tile `$DA6A`, X `$DA46` + `$013D`, attribute `$01`; write RAM `$0200+4*i..$0203+4*i`, `$010C+i`, `$0100+i`; set `$000C=12`, `$0466=01` | initialization branch |
| `$D9D8–$DA19` | 12 iterations; increment and wrap phase `$03AE` modulo 11; advance Y by `$40`, subtract `$BD` if >=; compute X from prior sprite's X (`$010B` for first) plus `$DA52[i]` and `$DA76[phase]` | update state branch |
| `$DA1A–$DA45` | Regenerate OAM: Y clipped to `$F8` if >= RAM `$013E`; tile `$DA6A`, attribute `$00`, updated X | update OAM branch |
| `$DA46/$DA52/$DA5E/$DA6A/$DA76` | Source data tables, respectively 12/12/12/12/11 bytes | Read from authenticated PRG, never hardcoded in production source |
| `$EE5A` | Existing source OAM DMA `$0200–$02FF` to PPU OAM | `stepOriginalOamDma` used in browser research panel |

**Evidence and tests:** `tests/original-weather-sprites.test.js` checks byte-for-byte initialization, updates, wrap, clipping, inactive state, unrelated-RAM preservation, authentic original machine-code bytes and tables. A separate, intentionally small test-only 6502 opcode interpreter (`tests/helpers/execute-weather-6502.mjs`) executes **the user's actual original `$D993` machine code** against 16 deterministic randomized RAM fixtures, 5 consecutive calls each (80 differential comparisons); native JavaScript and machine-code execution produce byte-identical 2 KiB RAM results. This is *isolated instruction-level parity on synthetic RAM*, not original NES reference gameplay-frame parity. The interpreter is not an emulator of the full NES, PPU, audio or mapper. The browser lab imports the owner's ROM in memory, verifies its header-normalized SHA-1 without relying on WebCrypto, and steps initialization/update into the existing source-derived OAM DMA. Desktop, modular and mobile-emulated Chromium tests include rejection of a modified PRG.

**Still missing:** original call order and invocation conditions for `$D993`, original RAM state before weather calls, original sprite CHR bank/palette and PPUCTRL mode at the same frame, weather visual parity, original **player** metasprite/animation producers, original NES runtime RAM/OAM reference traces. The lab uses an artificial initial weather state, X offset and Y clipping limit, and must not be described as original captured gameplay or a playable Classic game. The provisional football testbed remains isolated.
